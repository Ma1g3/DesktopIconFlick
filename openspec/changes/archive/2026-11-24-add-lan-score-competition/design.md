# Design

## Context

当前 `TrainingRound` 持有本地秒表、随机数、靶位和射击统计。开局时按本机 FOV 与视口宽高比计算靶位网格，因此仅共享随机种子不能对齐不同屏幕上的靶位。`TrainingWindow` 负责前台光标接管、Raw Input、失焦暂停和结算，所有已完成的对局目前都会更新本机个人最佳。构建使用 .NET Framework 4.8 的 C# 5 编译器。

## Goals / Non-Goals

目标

- 让房主统一管理开局时间、参赛名单和最终排名，单机和竞赛复用命中判定、补靶、渲染和桌面输入释放。
- 将网络处理与 WPF 输入、渲染隔离，使正常网络延迟只影响房间通信和结算等待。
- 保持旧配置文件、单机计时及个人最佳的兼容性。

范围

- 首版面向同一 IPv4 子网里的熟人对局，以手动输入地址进房为入口。公网匹配、房间发现、实时比分、掉线恢复本轮和历史榜属于后续独立功能。
- 首版成绩使用客户端报告，防作弊与远端重放校验留给需要更高信任强度的玩法。

## Decisions

### 房主进程维护权威房间

房主绑定所选本机局域网 IPv4 地址及显示给玩家的端口。多网卡环境允许选择地址。每个客户端建立一条 TCP 长连接，房主在连接建立后检查来源是否落在所选网卡的子网内。只在创建或加入房间后启动网络，由房间生命周期负责停止监听、取消连接任务及关闭套接字。显式地址让两台机器可以直接验证可达性。广播发现需要额外处理多网卡、广播限制和防火墙。

通过带长度前缀的 UTF-8 JSON 消息交换握手版本、房间快照、准备状态、时钟采样、开赛安排、最终成绩与结算。用 .NET Framework 自带的 TCP 和 JSON 序列化 API 构建，应用和测试共用所需的框架程序集引用。限制帧和昵称长度，校验消息类型、状态、版本和字段范围，通过连接绑定内部玩家标识。同名昵称在房间和结算使用同一个显示区分方式。后台处理网络读取、写入和超时，串行更新房间状态，再把快照交给 WPF Dispatcher。客户端与房主都用周期消息和超时识别静默断线。

### 单调时钟安排开局

用各端的单调时钟交换时间采样，在往返时间较短的样本上估算房主时间与本机时间的差值。客户端取得可用样本后才允许准备。房主接受开赛请求时冻结名单，分配本轮标识、新种子和 3 秒后的开局时点。客户端用最近的合格样本把同一个开局及截止时点映射到本机时钟，整轮使用这次映射。依赖每端收到消息时立即开跑会把传输和调度延迟直接算进开局差。使用 Windows 系统时间会把机器间时钟差和校时纳入计时。

按开局和截止时间点驱动倒计时及进度，定时器只负责唤醒。输入入口也检查同一个截止时点。开赛时重新验证准备授权、本机前台状态和鼠标接管是否成功，超过允许的开局延迟便标为未完赛。例如为网络时间估计预留 50 毫秒误差，为本地启动预留 150 毫秒，再通过双机验收确认开局偏差在 250 毫秒内。轻微晚启动的客户端沿用原截止时点。单机保留按活动时间累计的路径。

### 每轮共用角度网格，判定与渲染留在本机

竞赛使用固定的靶位角度网格与球形命中体。以现有支持的最窄视野和宽高比为设计下限，复用三靶间距及替换逻辑，并验证不同视口下的可见性。每轮用新种子初始化独立的竞赛随机序列。相同的种子与命中靶位顺序产生相同的靶位，玩家选中不同靶位时各自在本机演进。原有单机网格继续根据本机视口生成。

实时命中、音效与补靶使用已有的本机输入路径；相同角度网格由各自设置的 FOV 投影。若由房主逐枪判定，需要跨网传输瞄准输入并协调即时反馈。这里房主收到的是每轮最终命中与射击整数，统一计算命中率与并列排名。

### 对局结束、未完赛和重复消息

房间状态按等待准备、倒计时、进行中、收分、已结算推进。将本轮名单留在快照中，连接变化只更新参赛状态。每名玩家在每轮最多接受一个终态。客户端在本机截止时只提交一次成绩。房主按连接与轮次校验提交，检查 `0 ≤ 命中数 ≤ 射击数`。收分接受时间考虑约定的时钟估算误差，统一截止后最多再等 5 秒。迟到、重复或旧轮提交不会更改已确认的结果。断开前已经确认的成绩仍视为完赛。

`TrainingWindow` 在设置页提供建房与加入，并用大厅、倒计时、等待结算和计分板展示房间快照。每轮主动准备只授权本轮一次前台接管。失焦、放弃、显示坐标失效、输入失控和网络断开统一走已有的光标及反馈释放路径，竞赛截止已到的本地完成路径优先于标记放弃。房主放弃本轮后仍可主持房间，关闭房间则终止会话并取消未结算比赛。房主将已结算房间切回大厅后，所有在线玩家重新准备。

## Risks / Trade-offs

- Windows 防火墙、访客网络隔离或选错网卡会导致连接失败 → 显示监听失败、连接超时和不同协议版本等可区分的原因。在双机验收确认端口可达并检查失败提示。
- Wi-Fi 抖动或窗口线程忙可能使开局错过 → 使用开局前的时钟采样、明确的开始窗口与终止状态。用可控时钟覆盖边界，用两台电脑测量开局时间差。
- 房主进程退出或局域网突然失联 → 连接超时统一交回桌面输入。房主失联时客户端取消未收到正式结算的比赛。
- 房主依赖客户端报告命中数 → 校验基本字段与轮次，按熟人之间的友好比赛界定信任范围。

## Migration Plan

多人对局两端使用具有相同协议版本的构建。现有个人设置与单机个人最佳沿用原格式，房间和计分板只保留在内存。回退时替换为旧版应用及其配置伴随文件即可继续读取原来的个人设置。
