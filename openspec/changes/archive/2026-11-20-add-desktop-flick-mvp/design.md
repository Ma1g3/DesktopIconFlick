# Design

## Context

Windows 桌面原型已使用 Shell 素材和固定准星。现有绘制把图标放进圆形底板，补位会跟随当前视角分散到较大的范围。本次调整让图标本身占据靶位，并把连续补位限制在开局朝向附近。

## Goals / Non-Goals

**Goals:**
- 让桌面窗体、鼠标输入与对局核心分别可验证，尤其是暂停和结束时的光标释放。
- 让靶位、投影和命中判定与图标素材解耦，相同输入可以回放验证。

**Non-Goals:**
- 不嵌入 Explorer，不修改桌面窗口的可见性或层级。
- 不实现从真实图标位置起飞的开场动画；先验证图标素材辨识度和切靶手感。

## Decisions

1. **先用 C# / WPF 验证桌面效果。** 使用独立的无边框半透明前台窗体，按主屏工作区定位，不设为永久置顶，用户在露出桌面后显式开始。整个工作区在对局中都绘制非零透明度的底色并接收输入，不使用点击穿透样式。比桌面子窗口更容易控制焦点和失焦；比用壁纸截图伪装桌面更能保留真实、静止的背景。原型用 Windows 上的 .NET Framework 编译工具构建，不依赖本机尚未安装的 .NET SDK。
2. **前台相对输入和光标约束分开。** 通过 `WM_INPUT` 读取鼠标相对计数和主键按下事件，只在对局活动且有焦点时处理，不注册后台输入。隐藏光标并限制其活动范围只用于输入隔离，不参与视角计算。使用统一、可重复调用的释放路径处理 `Esc`、失焦、结算、显示配置变化、启动捕获失败和关闭；恢复必须由用户显式触发。
3. **核心维护固定的 3D 靶区。** 用 `360 × 2.54 / (DPI × cm/360)` 将每个鼠标计数换算为角度。按输入顺序先应用位移，再在主键按下时从虚拟相机中心发射判定射线，与最近相交的球体判定命中。开局根据视野和视口宽高比生成紧凑的候选点，避免补位随准星漂移。保留开局的中央空位，补位时依次检查与其他靶及刚命中的靶位的最小间隔。宽屏压缩纵向范围后仍有独立的横向位置可供补位。使用固定种子和可控时间验证连续命中。
4. **直接绘制 Shell 图标。** 枚举当前用户的 Shell 桌面项目并将图像缓存到进程内。以球形命中体的屏幕投影为尺寸基准，保持图标比例、方向和透明度，绘制在同一投影中心。图标模式在首次读取结束后可开始，普通小球可立即开始。素材读取失败或为空时回退为普通小球。
5. **状态与记录分开。** 显式管理待机、活动、暂停和结算状态；使用单调时间计算活动用时，忽略暂停输入及截止后的射击。设置和已完成对局的个人最佳保存在用户本地应用数据目录，不保存图标名称或路径；读取失败时用默认值并给出提示。
6. **在命中的原位显示壁纸。** 只读查找桌面项和包含文字的屏幕矩形，为活动靶绑定独立来源。Shell 枚举返回同名项目时，用 Explorer 桌面视图实际包含的项目身份进行配对，跳过已配对项目的同名备用素材。命中记录该来源，优先使用尚未命中的桌面图标补位。静态壁纸按 Windows 的显示方式和物理坐标绘制，从绘制范围内裁掉有可见应用窗口的区域。对于独立的 Wallpaper Engine 壁纸窗口，用 DWM 按原位坐标实时合成一块裁剪后的壁纸，放在桌面图标上方、普通窗口下方。训练暂停或结束时释放实时合成窗口。无法获得可靠背景时保留原位图标。

## Risks / Trade-offs

- [透明区域点击穿透] → 在真实图标和空白桌面上分别验证遮挡层，不依赖只给靶子做鼠标命中测试。
- [WPF 合成影响高刷新率手感] → 在原型验收时记录实际帧率与连续甩动体验；若未达可用手感，再评估独立 GPU 合成，不在首版同时实现两套渲染。
- [光标约束是共享状态] → 验证前台切换、捕获失败和强制终止，不假定普通关闭回调在崩溃时会运行；若强制终止后不能正常使用光标，修复输入方案后再验收。
- [DPI 或显示器布局变化导致坐标错位] → 将窗口、投影视口与光标约束坐标显式对齐，遇到布局变化先结束对局，再重算工作区。

## Migration Plan

继续读取已有的外观设置、灵敏度和个人最佳记录。应用只读访问 Shell 素材，退出时可直接关闭训练层。
