# 桌面验收

## 开始前

在有 Explorer 的交互式 Windows 10/11 x64 会话运行 `.\bin\DesktopIconFlick.exe --measure`，先露出主屏桌面。记录系统版本、分辨率、主屏与副屏排列、各屏缩放及系统刷新率；至少覆盖默认缩放和一组不同缩放，并覆盖有副屏的布局。准备一个无害的桌面测试图标，不要对重要文件做输入测试。

## 画面与手感

1. 等待图标加载后开始一局。确认三枚靶直接显示可辨认的桌面图标，透明处能看到下方画面，靶子周围没有圆形底板或边框。移动鼠标时观察游戏靶和固定准星，核对壁纸、真实图标、任务栏和副屏。
2. 将测试图标放在工作区中心，记录其选中状态。在能看到真实图标的空白游戏画面上单击、按住，再打中经过该位置的游戏靶。每次按下只记一次；真实图标不被选中、打开或拖动。测试结束后手动归还测试图标位置。
3. 连续命中至少十枚靶，观察每次是否只替换命中的一枚，在同一片区域立即补位，并保持三枚靶彼此可辨。在 60° 和 120° 水平 FOV 各试一次，确认对准一枚后视野内仍能看到另外两枚。再切换到普通小球，确认圆靶绘制和补靶节奏。
4. 在同一硬件 DPI 下用标记固定鼠标物理行程，分别在两组 Windows 指针速度设置下比较转向幅度，结束后恢复原设置。固定的物理行程应得到相同转向。用图标和小球分别打完一局，检查计时、统计、重开和个人最佳。
5. 两局内分别持续左右快速甩动。结算后检查 `%LOCALAPPDATA%\DesktopIconFlick\measurements.log` 中的两条记录，核对 `appearance` 分别为 `icons` 和 `balls`、`move_packets` 大于零，并记录是否卡顿或丢失输入。日志只保存相对位移包数，不保存具体鼠标轨迹。 `monitors` 是屏幕数量，`primary_hz` 是 Windows 报告的主屏刷新率（0 表示未知）；`render_callbacks_per_second` 是去重后的 WPF 回调频率，不是显示端测得的 FPS。
6. 露出主屏桌面，用静态壁纸开始图标局。观察从开局到命中的变化。打空时原位图标继续可见，命中后对应图标及文字由同位置的壁纸盖住。用两个同图案但不同名称的图标核对对应关系。按 `Esc` 检查原位图标重现，点击继续检查遮盖恢复；结算和重开时检查所有图标都可见。测试结束后核对 Explorer 的图标位置和文件。
7. 若桌面使用 Wallpaper Engine，命中后核对原位的实时画面。观察图标边缘外的动画是否连续，并确认暂停、继续和退出时的显示。若有其他窗口挡住原位、图标无法定位或切换到普通小球，核对这些命中仍正常补靶。
8. 分别在图标和小球模式里命中及打空。命中应出现准星提示和一声短音，打空只增加射击数。关闭「命中音效」后退出并重启，确认命中仍有视觉提示且保持静音。图标原位首次露出壁纸时应出现短暂淡出的角线。用测试窗口挡住原位的部分和全部，观察提示范围。命中后立刻暂停再继续，确认原有遮盖恢复，刚才的提示不重播。
9. 观察 HUD 的时间、命中数、射击数和靶外观。让命中或射击数从一位变成两位，确认信息位置稳定。检查零射击、追平和新纪录时的结算。超过既有正数纪录时应显示多命中的数量。「再来一局」应把本局统计归零。

## 输入生命周期

- 活动期间按 `Esc`、切至其他窗口，分别检查光标立即可用、暂停不扣时、回焦不自动恢复、点击继续才接管。
- 在对局中改变显示缩放或主屏配置，确认该局停止并提示重开；新局的覆盖范围符合新的主屏工作区。
- 在后台状态尝试从自动化工具触发开始（不要激活训练窗口），检查不会获取光标；正常回到前台点击开始仍可用。
- 在对局中正常关闭、等到结算、用测试工具强制结束本次原型进程，分别检查鼠标可在各屏移动并点击其他窗口，桌面图标布局不变。

## 局内 DPI

1. 打开新版设置页。确认默认显示局内 DPI 和水平 FOV，高级校准收起。用 Tab 进入输入框、展开高级校准，然后到达「开始训练」。在非 100% 缩放下确认文字完整可见。
2. 保持硬件档位和水平 FOV，分别用 800 和 1600 局内 DPI 开局。从相同初始朝向用实体鼠标沿标记移动相同的短距离，1600 的训练转角应约为 800 的两倍。暂停或退出后核对桌面光标活动及 Windows 指针速度和加速度设置。
3. 在高级校准中填硬件 DPI 800、转身距离 40，应用后局内 DPI 应为 800。再只把转身距离改为 20，应用后局内 DPI 应为 1600。实体鼠标测试时使用鼠标当前档位作为校准输入。用超出范围的值测试局内 DPI 和高级校准，两处都应提示有效范围并保留上一组有效设置。
4. 重新启动，确认局内 DPI 已保存，高级校准仍收起。用五行或六行的旧设置文件启动时，核对可按旧值换算出等效局内 DPI，并保留原有视野、外观、音效和个人最佳。

## 提交验收结果

在 PowerShell 7 中读取最近两局记录：

```powershell
Get-Content -LiteralPath "$env:LOCALAPPDATA\DesktopIconFlick\measurements.log" -Tail 2
```

附上另一组缩放、双屏排列和画面/输入检查结果。日志不能证明叠层拦截点击或强制结束后光标可用，这两项需另行确认。

## 当前验证记录

- Windows 11（构建 22621），单屏物理分辨率 2560×1440、120 DPI（125%），系统报告主屏 240 Hz。原生窗口可响应，其 2560×1380 边界与主屏工作区一致，底部 60 物理像素预留给任务栏；启动未接管光标。240 Hz 不是实测游戏帧率。
- Windows 原生命中测试确认四角内侧的半透明空白采样点都落到训练窗，而不是底层窗口；未注入点击，也未对真实桌面图标执行操作。
- 已通过 x64 构建、核心测试、Shell 图标读取、光标接管状态回归和两种外观的离屏渲染。
- 2026-11-18 在上述单屏环境进行了桌面自动验收。看到图标和小球模式分别显示三枚靶与固定准星；空白位置单击和按住拖动各只记一次未命中，两局约 30 秒后正常结算。
- `Esc` 暂停后剩余 19.0 秒保持不变，并用系统接口确认光标不再受限；点击继续后完成结算。另测得 `Alt+Tab` 切出会暂停，重新聚焦仍为暂停。强制结束测试进程前，系统报告光标约束为 1×1 像素；进程退出后确认恢复为整个虚拟桌面。
- 图标局 30.004 秒、143.4 次 WPF 渲染回调/秒；小球局 30.003 秒、230.1 次/秒。两局日志的 `move_packets` 都为 0：自动化拖动未产生可用的相对位移，不能用这些数据判断持续甩动时的表现。
- 尚未覆盖物理鼠标甩动及系统指针速度对照、靶与真实图标重叠时的点击、显示配置变化、另一组缩放及双屏边界。测试未改动系统显示设置或真实图标。
- 2026-11-19 在 Windows 11（构建 22621）、2560×1440 单屏、125% 缩放、240 Hz 下复验。主屏工作区为 2560×1380。启动时光标自由，叠层的四个空白采样点均命中训练窗口。实机观察到三枚桌面图标紧靠准星周围且没有圆形底板。图标与小球各完成一局，小球局经 `Esc` 暂停并手动继续。两局均无物理鼠标位移样本。
- 同日的自动回归通过 18,000 次固定种子补靶，对比 60°、100°、120° 水平 FOV 和 9:16 至 32:9 的五组宽高比，并核对图标透明区域与无图标时的小球回退。
- 同一 Windows 会话的只读探针匹配了 34 个可单独定位的桌面图标并确认 Wallpaper Engine 会启用深色遮盖。离屏回归核对单个原位遮盖、同图案项目独立处理、暂停恢复、位置变更及被其他窗口挡住时的行为。实机尚缺物理鼠标命中后的画面和手感验证。
- 同一单屏会话在前台训练窗复现全透明辅助窗口阻止全部原位遮盖。修复后，用训练窗的对局输入入口触发三次命中，逐一确认原位深色遮盖已绘制。暂停后，三处遮盖均撤回，光标恢复自由。原生窗口回归还验证了不透明和半透明窗口继续限制遮盖，局部遮挡回归验证了只绘制露出部分。
- 在同一 125% 缩放会话，以训练窗口的输入入口复验 Wallpaper Engine。打空未产生遮盖，命中后原位显示实时动画，取样的 144 个像素中有 143 个随动画变化。暂停时合成窗口销毁，原位图标恢复，继续训练后实时合成重新出现。核对 Explorer 图标位置与命中前一致。
- 2026-11-20 在同一会话复验「控制面板」。Shell 返回两个同名项目，Explorer 桌面视图只包含其中一个。新版只加载一份对应原位的素材，命中后注册了该矩形的实时壁纸，暂停时合成窗口被释放。测试时另一个应用盖住原位，因此只核对了合成范围和 Explorer 坐标。
