# 桌面验收

## 开始前

在有 Explorer 的交互式 Windows 10/11 x64 会话运行 `.\bin\DesktopIconFlick.exe --measure`，先露出主屏桌面。记录系统版本、分辨率、主屏与副屏排列、各屏缩放及系统刷新率；至少覆盖默认缩放和一组不同缩放，并覆盖有副屏的布局。准备一个无害的桌面测试图标，不要对重要文件做输入测试。

## 画面与手感

1. 等待图标加载，确认壁纸和任务栏原样可见。开始一局，在主屏内观察鼠标移动时只有游戏靶移动，准星固定；真实图标不动，第二个屏幕不被盖住。
2. 将测试图标放在工作区中心，记录其选中状态。在能看到真实图标的空白游戏画面上单击、按住，再打中经过该位置的游戏靶。每次按下只记一次；真实图标不被选中、打开或拖动。测试结束后手动归还测试图标位置。
3. 在同一硬件 DPI 下用标记固定鼠标物理行程，分别在两组 Windows 指针速度设置下比较转向幅度，结束后恢复原设置。固定的物理行程应得到相同转向。用图标和小球分别打完一局，检查计时、统计、重开和个人最佳。
4. 两局内分别持续左右快速甩动。结算后检查 `%LOCALAPPDATA%\DesktopIconFlick\measurements.log` 中的两条记录，核对 `appearance` 分别为 `icons` 和 `balls`、`move_packets` 大于零，并记录是否卡顿或丢失输入。日志只保存相对位移包数，不保存具体鼠标轨迹。 `monitors` 是屏幕数量，`primary_hz` 是 Windows 报告的主屏刷新率（0 表示未知）；`render_callbacks_per_second` 是去重后的 WPF 回调频率，不是显示端测得的 FPS。

## 输入生命周期

- 活动期间按 `Esc`、切至其他窗口，分别检查光标立即可用、暂停不扣时、回焦不自动恢复、点击继续才接管。
- 在对局中改变显示缩放或主屏配置，确认该局停止并提示重开；新局的覆盖范围符合新的主屏工作区。
- 在后台状态尝试从自动化工具触发开始（不要激活训练窗口），检查不会获取光标；正常回到前台点击开始仍可用。
- 在对局中正常关闭、等到结算、用测试工具强制结束本次原型进程，分别检查鼠标可在各屏移动并点击其他窗口，桌面图标布局不变。

## 提交验收结果

在 PowerShell 7 中读取最近两局记录：

```powershell
Get-Content -LiteralPath "$env:LOCALAPPDATA\DesktopIconFlick\measurements.log" -Tail 2
```

附上另一组缩放、双屏排列和画面/输入检查结果。日志不能证明叠层拦截点击或强制结束后光标可用，这两项需另行确认。

## 当前验证记录

- Windows 11（构建 22621），单屏物理分辨率 2560×1440、120 DPI（125%），系统报告主屏 240 Hz。原生窗口可响应，其 2560×1380 边界与主屏工作区一致，底部 60 物理像素预留给任务栏；启动未接管光标。240 Hz 不是实测游戏帧率。
- Windows 原生命中测试确认四角内侧的半透明空白采样点都落到训练窗，而不是底层窗口；未注入点击，也未对真实桌面图标执行操作。
- 已通过 x64 构建、核心测试、Shell 图标读取、光标接管状态回归和两种外观的离屏渲染。
- 2026-11-18 在上述单屏环境进行了桌面自动验收。看到图标和小球模式分别显示三枚靶与固定准星；空白位置单击和按住拖动各只记一次未命中，两局约 30 秒后正常结算。
- `Esc` 暂停后剩余 19.0 秒保持不变，并用系统接口确认光标不再受限；点击继续后完成结算。另测得 `Alt+Tab` 切出会暂停，重新聚焦仍为暂停。强制结束测试进程前，系统报告光标约束为 1×1 像素；进程退出后确认恢复为整个虚拟桌面。
- 图标局 30.004 秒、143.4 次 WPF 渲染回调/秒；小球局 30.003 秒、230.1 次/秒。两局日志的 `move_packets` 都为 0：自动化拖动未产生可用的相对位移，不能用这些数据判断持续甩动时的表现。
- 尚未覆盖物理鼠标甩动及系统指针速度对照、靶与真实图标重叠时的点击、显示配置变化、另一组缩放及双屏边界。测试未改动系统显示设置或真实图标。
